# pending-work.ts：持久待办与事件恢复

`pending_work` 只挂起一个未完事项。主会话仍可处理消息、选择其他行动和向 World 提交任务。
事项由 Persona 的 Memory 文件 `pending-work.json` 保存；Core 定时器只保存到期索引。

## 工具契约

| operation | 行为 |
| --- | --- |
| `defer` | 保存意图、新证据条件与回访时间；立即返回待办 id |
| `list` | 分页读取待办，默认只显示活跃事项 |
| `resolve` | 模型核验结果后结清指定事项 |
| `cancel` | 取消指定事项及其定时器 |

`defer` 提供 `note`，并至少提供 `after_seconds` 或 `wait_for` 中一项。
`wait_for` 可包含 `source`、`type`、`sender_key`、`contains`；提供的条件按 AND 匹配。
`contains` 使用区分大小写的字面文本。事件须在登记之后产生；内部提醒不会触发外部等待条件。
使用已有 `id` 再次 `defer` 会更新该事项并替换旧定时器。

回执、列表、摘要与复核提醒都用 `id="原始值"` 展示 ID；引号内按 JSON 字符串转义，
调用时传回原始字符串值。原始 ID 最长 80 字符，允许包含 `#`，持久化格式不变。
查找始终优先精确 ID。精确 ID 不存在时，仅将旧展示添加的一层前导 `#` 作为
兼容别名，且必须命中已有条目；`defer` 命中后更新原条目，不创建副本。
最长 ID 的旧展示输入可为 81 字符，但未知的新 ID 仍限 80 字符。
已有 `foo` 而没有 `#foo` 时，输入 `#foo` 更新 `foo`；没有对应条目时，
新建的 `#foo` 按原值保存。已有的合法 `#foo` 始终精确命中，不会改成 `foo`。

```json
{
  "operation": "defer",
  "note": "等对方确认刚才的问题；收到消息后核对实际结果",
  "after_seconds": 120,
  "wait_for": { "source": "chat", "sender_key": "partner" }
}
```

例中的来源和发言者需要换成实际 World 提供的值。发送问话成功只证明已经发送，
不证明对方回复，也不证明目标完成。

## 状态与投递

`waiting` 在匹配的新外部事件到达，或复核时间到达后，变为 `ready`。
Persona 保存触发时间、事件游标和精简证据，并注入一次复核提醒。
`ready` 表示有线索可检查；最终 `resolved` 或 `cancelled` 由模型明确选择。
事件先到会取消该事项的定时器，避免到期后重复通知。

Memory 原子替换成功后才发布新状态、移除旧定时器和注入复核提醒。
保存失败会保留原记录与运行态；同一操作可以重试，新建的未提交定时器会撤销。

主会话每次获取一份稳定、最多 1600 字符的活跃摘要。完整记录留在 Memory，
`list` 分页读取；结束回合和上下文交接不清空待办。重启时恢复等待索引，
离线期间到期的事项转为待复核，已有终态不会重新执行。

## 并发边界

| 部分 | 执行方式 |
| --- | --- |
| 等待消息、预约复核 | 事件匹配与持久定时器，不占据模型调用 |
| 主会话决策 | 逐批处理事件，选择当前可行事项 |
| 后台记忆整理、World 请托构思 | 现有独立 fork；待办工具不创建额外模型循环 |
| 游戏走路、战斗和容器操作 | 由对应 World 的身体执行器排队，避免争抢控制 |

待办匹配不调用模型、不等待远程服务，也不安装全局投递闸门。
新能力归 Persona；Core 不解释事项内容，World 不依赖具体 Persona 的待办实现。
